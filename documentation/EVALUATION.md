# Evaluation Framework 🧪

To guarantee enterprise-grade reliability and prevent LLM hallucinations, this project utilizes **DeepEval** to rigorously benchmark the LangGraph application.

## ⚙️ How It Works

Instead of relying on human evaluation (which is slow) or cloud APIs (which can be expensive and expose private data), we use a **Local LLM-as-a-Judge**. 

Specifically, we use the `gemma4:e4b` model via Ollama to grade the responses of our primary application.

### The Metrics
Every test case is graded (0.0 to 1.0) against three critical DeepEval metrics:

1. **Contextual Relevancy:** Evaluates the `retrieval_context`. If the system retrieves large chunks of irrelevant text alongside the correct answer, this score drops. (We solved context dilution by implementing a strict `\n\n` chunking strategy).
2. **Faithfulness:** Evaluates the `actual_output` against the `retrieval_context`. If the LLM hallucinates an answer or provides information not found in the retrieved company policies, it is penalized.
3. **Answer Relevancy:** Evaluates the `actual_output` against the original `input`. Ensures the final synthesized response directly answers the user's question without unnecessary rambling.

## 📂 The Test Suite (`data/comprehensive_eval_questions.json`)

We have procedurally generated a robust 50-question test suite designed to push the Intent Router and Synthesizer to their limits:

- **Questions 1-15 (Happy Path):** Single-domain, direct questions to establish a perfect baseline (e.g., "How many sick leaves do I get?").
- **Questions 16-30 (Multi-Domain Routing):** Questions querying multiple domains simultaneously to ensure the router triggers correctly (e.g., "How many sick leaves do I get, and is VPN mandatory?").
- **Questions 31-40 (Edge Cases):** Situations with conflicting keywords designed to confuse the router (e.g., "I lost my laptop while on maternity leave").
- **Questions 41-50 (Negative Constraints):** Completely out-of-domain questions to ensure the agent replies with "I could not find this information" instead of hallucinating (e.g., "What is the policy for dog insurance?").

## 🚀 Running the Evaluations

To run the automated test suite, use the provided Python script:

```bash
python3 scripts/run_automated_tests.py
```

### Options
Because running 50 full evaluations through a local LLM can take 15-30 minutes, you can use the `--limit` flag to test a smaller subset during active development:
```bash
python3 scripts/run_automated_tests.py --limit 5
```

### The Evaluation Report
Instead of printing massive text blobs to the terminal, the script automatically formats and saves the results to `logs/evaluation_report.md`. 

You can open this markdown file to see the exact Reason and Score generated by the Ollama judge for every single question!
